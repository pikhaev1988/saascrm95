# Справка об информационной безопасности

Платформа «Анализ ГИА»  
Правообладатель: Пихаев Амур Адланович, ИНН 201005220670  
Дата: 18.08.2026

Документ описывает фактические меры защиты. Это не аттестат ФСТЭК и не сертификат соответствия ГОСТ.

---

## 1. Назначение системы

Закрытый веб‑кабинет для анализа протоколов ГИА и ВПР. Пользователи — уполномоченные сотрудники школы, района или органа управления образованием.

---

## 2. Модель доступа

- вход только по учётной записи (логин и пароль);
- роли: школа, район, министерство;
- школа видит только свою организацию;
- API по умолчанию требует аутентификации;
- сессии защищены флагами `HttpOnly`, `Secure`, `SameSite`;
- пароли хранятся в виде хеша (стандарт Django), не в открытом виде;
- действуют правила сложности пароля.

Административный доступ к серверу и базе есть только у правообладателя.

---

## 3. Защита канала и приложения

- HTTPS, перенаправление с HTTP;
- HSTS;
- защита от CSRF;
- заголовок `X-Content-Type-Options: nosniff`;
- ограничение встраивания страниц (`X-Frame-Options`), кроме служебных выгрузок файлов;
- доверенные origin для CSRF;
- журнал обращений к чувствительным адресам (выгрузки, загрузки) с идентификатором запроса, пользователем, ролью и IP.

Исходные протоколы сохраняются как загруженные файлы и привязываются к школе, которая их направила.

---

## 4. Персональные данные

Обрабатываются персональные данные обучающихся (в том числе несовершеннолетних), потому что они есть в протоколах ГИА/ВПР: ФИО, класс, результаты.

Правовая схема, которую нужно закрепить договором:

- школа (или учредитель) — оператор персональных данных;
- правообладатель платформы — обработчик по поручению школы (ч. 3 ст. 6 Федерального закона № 152‑ФЗ).

Обязанности обработчика в договоре:

- обрабатывать данные только для аналитики и отчётов этой школы;
- не передавать данные третьим школам;
- не использовать данные для рекламы;
- удалить или вернуть данные по окончании доступа по письменному запросу школы, если закон не требует хранить их дольше.

Место обработки: Российская Федерация.

## 5. Субпроцессоры

| Кто | Зачем | Что уходит |
| --- | --- | --- |
| Beget | Размещение сайта, базы и файлов | Все данные кабинета |
| GigaChat (Сбер) | Стилистика аналитических текстов | Агрегированные показатели, без ФИО и без файла протокола |

Школа вправе запретить использование GigaChat дополнительным соглашением. Тогда тексты справок останутся шаблонными, расчёты не меняются.

## 6. Резервное копирование и инциденты

- размещение на хостинге в РФ;
- восстановление из резервных копий хостинга и/или выгрузки базы по регламенту правообладателя;
- о инциденте, который затрагивает персональные данные школы, правообладатель уведомляет школу без необоснованной задержки.

Регламент хранения протоколов рекомендуется согласовать со школой: например, текущий учебный год плюс `[N]` лет либо удаление по заявке.

---

## 7. Чего у платформы нет — и это нормально

Школы иногда просят «сертификат безопасности». У коммерческого кабинета аналитики обычно нет и не требуется:

- аттестат соответствия ФСТЭК;
- сертификат ГОСТ Р ИСО/МЭК 27001;
- лицензия ФСБ на криптографию;
- лицензия на образовательную деятельность.

Эти документы нужны государственным информационным системам, операторам связи, удостоверяющим центрам — не школьному кабинету аналитики протоколов.

Что можно показать вместо этого:

1. Настоящую справку.
2. Свидетельство Роспатента о регистрации программы для ЭВМ (после получения).
3. Договор с поручением на обработку ПДн.
4. Уведомление в Роскомнадзор (после подачи).
5. При необходимости — выписку из реестра российского ПО (отдельная процедура).

---

## 8. Обязанности школы

- назначать доступ только своим работникам;
- не передавать логин третьим лицам;
- загружать только протоколы своей организации;
- иметь законное основание на обработку данных обучающихся (как оператор);
- сразу сообщать, если сотрудник со доступом уволился — учётную запись отключат.
